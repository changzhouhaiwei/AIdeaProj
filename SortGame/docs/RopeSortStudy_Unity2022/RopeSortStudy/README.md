# Rope Sort! 1.0.2 关卡与 Unity 2022 学习工程

## 打开与操作

用 Unity Hub 添加 `UnityProject` 文件夹，以 Unity **2022.3.62f3** 打开（代码目标为 Unity 2022.3）。打开 `Assets/Scenes/Study.unity` 后点击 Play。没有场景时可用菜单 `Rope Sort > Create Study Scene` 重建。

点击任意元素选中它和其上方的整段，然后点击目标列的 `Move here`。支持上一条、下一条、按 key 搜索、重开、撤销、取消选择和增加一条临时绳列。顶部显示容量、目标收集数和补入队列剩余量。灰色问号表示隐藏元素，LOCK 表示冻结列。界面使用编号与颜色帮助学习；没有复刻原美术、音效和绳子动画。

演示默认打开固定第 1 关 FIXED/1/1；上一条和下一条仍按资源索引浏览，**不是原游戏玩家的闯关顺序**。可搜索 `FIXED/` 浏览固定关配置；其中显示的 difficulty=0 是未知占位，不是原难度值。这个版本是 Windows/Editor 本地研究原型，尚未适配 Android StreamingAssets 的读取方式。

## 配置字段

唯一键为 `group/pool/entryId`；entryId 是资源记录 ID，不是玩家进度关卡编号。

`raw` 保存原始配置串。`capacity` 是单列容量，`boardCount` 是初始列数，`groupsTotal` 是整局需要收集的目标列总数。`initial` 为开局列，`incoming` 为收集成功后按顺序消费的全局补入队列。

每列包含 `targetColor`（-1 表示无目标的临时列）、`beads`（**从绳子上端到下端，最后一个元素是可暴露的栈顶**）、`lock`。每个元素保存真实 `color` 和 `hidden` 标记。锁分为 `none`、`collect_count` 和 `collect_type`，后者额外包含颜色。后续出现的计数锁会按已完成数量转换为绝对解锁门槛，见 `CloneForAppearance`。

原始紧凑串格式是 `容量;初始列数:列;列;...`。每列为 `目标色[,冻结参数].元素串[.位置,掩码...]`。颜色使用 Base62 `0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ`；空目标表示临时列，元素最后一位是栈顶。冻结参数 `1N` 为收集数量条件，`2CN` 为指定颜色 C 的数量条件；隐藏元素掩码按每字符 5 位组合。完整解析和校验请以 `ColorSortLatticeParser.cs` 为准。

## 已核对的核心玩法

1. 可从列中任意位置切取到栈顶的整段，段内**不要求全部同色**。目标为空时允许放入；目标非空时，切口元素必须可见且颜色与目标栈顶相同。总容量必须够，源列与目标列不能被冻结。
2. 有目标色的列，只有满容量且全部元素等于目标色，才被收集。临时列不会自行收集。
3. 收集后完成数加一，消费补入队列下一项，替换目标和内容；可以变成临时列，或在队列耗尽后退出盘面。新内容按原 `PlaceBatch` 分配逻辑放入可用列。
4. 收集会推进冻结条件；移动后暴露到栈顶的隐藏元素会揭示。支持连锁收集。
5. 完成数达到 `groupsTotal` 即胜利。保留原可用移动、必败和有限闭环判定；有限搜索不能当作全局可解性证明。
6. 额外绳列每局限一次，最大总列数 9。演示撤销保存完整状态，包含收集、补入、揭示、冻结以及额外绳列。

## 程序来源与范围

安装包确有 arm64 `libil2cpp.so`，但核心玩法恰好在 Brotli 压缩的 Hot 托管热更新程序集中保留了完整 IL，因此本工程主要依据这些可读 IL 恢复，并非凭名称猜写规则。`global-metadata.dat` 使用非标准 HTPX 包装，未宣称完成原生 IL2CPP 全量反编译或解出其版本。具体核查信息在 `Evidence/native_inventory.json`。

核心类保留原命名便于对照。收集物类仅移除了依赖外部 MemoryPack/ES3 的序列化包装，保留玩法部分。演示未接入广告、商业化、账户存档、远程实验和动态能力调度，也没有接入原提示求解器。原游戏有固定规则、动态选池、玩家能力和实验组分支；**不能从离线关卡库保证“某个玩家第 N 关”的唯一配置**。本包提供离线库所有记录和已解析的默认匹配规则，远程覆盖不在本包内。

## 验证

- 101,703 条池布局通过恢复的原解析器与 `Validate`：0 错误。
- 16 条固定布局通过同样校验：0 错误。
- 池布局抽样执行 11,361 次合法移动→撤销状态比对；固定布局另执行 3 次：全部通过。
- Unity 2022.3.62f3 实际批处理编译成功，生成 `Study.unity`。
- Unity 实际加载三组池首尾共 6 个样本成功。测试日志保留在 Evidence；未进行完整人工视觉验收，也没有证明所有布局均可解。

源码中的配置解析与玩法可独立于 MonoBehaviour 使用：先 `ColorSortLatticeParser.Parse(raw, null)`，然后 `Validate`、`ColorSortRules.MakeState`，通过 `ApplyMove(state, level, src, cutIndex, dst)` 推进，`IsWin` 判胜。
