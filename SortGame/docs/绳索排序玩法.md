# 绳索排序玩法

依据 `docs/RopeSortStudy_Unity2022` 里恢复的规则整理。判定以 `ColorSortRules` 为准，关卡串解析以 `ColorSortLatticeParser` 为准。这份文档只写盘面怎么玩，不含广告、账号和远程选关。

玩家进度第 N 关不是库里的唯一布局。离线库是候选池加匹配规则，同一进度编号可以对应多条配置。

## 一局在做什么

盘面上是若干根绳子。每根绳子是一列珠子，上端挂在盆上，下端是露出来的自由端。玩家从某根绳子上选一颗珠，连同它下面挂着的整段，接到另一根绳子的自由端上。

有目标色的绳子，在装满且整列都是目标色时收走，计一次完成。完成数达到本关目标组数即过关。

珠子在数据里从绳子上端排到下端，**最后一个是自由端**。界面上从下往上点，点到的那颗就是切口，切口和它下面的珠一起搬走。

## 盘面

| 概念 | 含义 |
| --- | --- |
| 容量 | 一根绳子最多挂几颗珠。库里常见 4、5、6，MF1 有 1 关是 3 |
| 初始列 | 开局就在盘上的绳子。库里常见 6 或 7 列，加载时至少 3 列 |
| 目标色 | 这根绳子要收成的颜色。`-1` 表示没有目标，是临时绳 |
| 目标组数 | 本关必须收走的目标绳次数。过关条件是完成数 ≥ 目标组数 |
| 补入队列 | 每成功收集一次，按顺序消费下一条，换掉刚空出来的那根绳 |
| 隐藏珠 | 真实颜色已知，但玩家看到问号。编码是颜色加 1000 |
| 冻结 | 锁住整根绳，锁定期间不能作为源，也不能作为目标 |

开局列里不能出现「退出盘面」。自由端不能是隐藏珠，补入队列里每一段的自由端同样不能是隐藏珠。

列数上限写在代码里：基础上限 8，加上额外绳后总上限 9。运行时真正拦住额外绳的是「本局只用一次，且当前列数已到 9」。

## 移动

一次移动由三样东西决定：源列、切口下标、目标列。搬走的是源列从切口到自由端的整段，段内**可以混色**。

合法条件：

1. 源列和目标列都没有被冻结，且不是同一列。
2. 目标列剩下的空位够放下整段。
3. 目标列是空的：任意切口都能放，切口是隐藏珠也可以。
4. 目标列不是空的：切口那颗必须是明珠，并且颜色等于目标列当前的自由端。隐藏珠不能当切口接到有珠的绳子上。

接到目标列时，切口贴在对方自由端上，原自由端仍是新的自由端。例如源列自上而下是 A B C D（D 为自由端），从 B 切开接到自由端为 Y 的绳子上，结果是 `… Y B C D`，颜色核对的是 B 和 Y。

不合法时的原因：列非法为 `Invalid`，冻结为 `Locked`，空位不够为 `Full`，切口是隐藏珠为 `Mystery`，颜色不同为 `Color`。

## 揭示

移动（以及本步触发的收集、补入）全部结算后，检查每根还在盘上的绳子。自由端若是隐藏珠，立刻翻成明珠。埋在中间的隐藏珠保持问号，直到它自己变成自由端。

## 收集

一根绳子同时满足下面四条才会被收走：

1. 没有被冻结。
2. 有目标色。临时绳不会自己收集。
3. 珠数正好等于容量。
4. 每一颗的颜色都等于目标色。隐藏珠的编码和目标色不相等，所以问号还在列上时收不走。

收走后：珠子清空，完成数加一，这根绳的目标色记入「已收集颜色」。然后用**收集前的完成数**去取补入队列的下一条，决定这根绳接下来是什么。

| 补入槽 | 结果 |
| --- | --- |
| `jar` | 换成新的目标色，可以带一批新珠，也可以带一把新锁 |
| `park` | 变成临时绳，没有目标色。本关剩余的后补临时绳计数减一 |
| `retire`，或队列里已经没有下一条 | 这根绳离开盘面，容量变成 0，之后不能再放珠 |

补入条数在加载时会被补齐到「目标组数 − 1」。多出来的空位都是 `retire`。所以最后一次收集通常会让绳子离场，而不是再变出新目标。

新珠不是整段塞回原绳，而是按颗分配：先看刚清空的那一列，再按列号看其余列。每一颗放进第一根「没锁、还有空位」的绳子末端，因此新珠会成为那根绳的新自由端。某个位置放不下就停，后面的珠不再放。

收集可以连锁。一轮里所有已经满足条件的绳子都会收走，补入可能让别的绳子也凑满，最多再扫 40 轮。

## 冻结

锁在整根绳子上，不在单颗珠上。锁定时这根绳不能搬出，也不能搬入。

| 类型 | 原始参数 | 解开条件 |
| --- | --- | --- |
| `collect_count` | `1N` | 本局完成数 ≥ N |
| `collect_type` | `2CN` | 已收集颜色里，颜色 C 的次数 ≥ N |

`collect_count` 写的是「再收集这么多次」。绳子是后来补上盘面的时候，门槛会加上当时的完成数，变成绝对数。例如已经完成 3 次，新绳带的是「再收 2 次」，实际要完成数达到 5 才开。`collect_type` 不改数字，一直数某种颜色被收走了几次。

锁只在发生过收集的那一步之后检查。收完、补完，再把已经达标的锁清掉。只搬家、没有收集时，完成数不变，锁也不变。

## 额外绳

每局限一次。使用后增加一根空的临时绳：没有目标色，没有锁，容量与本关相同。当前绳子已经有 9 根时不能再加。这根临时绳自己不会被收集，用来腾位置。

撤销要连这根绳子一起撤回。演示里额外绳是单独一步，不附带搬家。

## 胜负

- 胜利：完成数 ≥ 目标组数。
- 必败：还可能凑出的满组数，已经小于还差的组数。满组数按颜色计算，盘上剩余珠加上还没发出的补入珠，每种颜色能凑多少个「容量」再相加。
- 无路：没有任何一次合法移动。
- 有限闭环：从当前局面出发，在不做收集的前提下互相可达，并且走不到任何一次收集。搜索最多记 80 个状态，超过就不判闭环。盘上还有隐藏珠或锁时，这条判断更严。它只说明这一小片状态出不去，不能当成整关无解的证明。

演示里的失败提示是「无路、必败、有限闭环」三者之一。撤销和重开仍然可用。

## 关卡串

唯一键是 `组/子池/记录号`。记录号是资源 id，不是玩家看到的关卡号。

紧凑串：

```text
容量;初始列数:列;列;列...
```

冒号前是头部。冒号后先是开局的每一列，列数等于头部第二个数；再往后每一段都是补入，按收集顺序消费。

一列：

```text
目标色[,冻结参数].珠串[.位置,掩码...]
```

- 颜色用 Base62：`0-9`、`a-z`、`A-Z`，一个字符一种颜色。
- 目标色留空表示临时绳。
- 珠串从绳子上端写到下端，最后一字符是自由端。
- 冻结参数跟在目标色后面，用逗号分开。`1N` 是收集次数锁，`2CN` 是指定颜色 C 的次数锁。N、C 也是 Base62。
- 隐藏不用问号直接写在珠串里。珠串后面用「位置 + 掩码」标出哪些下标是问号，掩码每字符 5 位，最低位为 1 表示隐藏。自由端不能标成隐藏。

解析之后的内部列是 `目标色|珠,珠,?珠`。`x` 表示补入后退出盘面，只能出现在补入段。

目标组数不是头部字段，而是整串里「有目标色的列」的个数，开局列和补入列都算。

## 库里的规模

这些数字描述离线库，不描述玩家会依次打到的关卡表。

| 池 | 子池 | 布局条数 | 难度区间 |
| --- | ---: | ---: | --- |
| GP101 | 416 | 50,529 | 18–1656 |
| GP201 | 425 | 50,525 | 18–1688 |
| MF1 | 1 | 649 | 2–650 |

按配置原文去重后是 51,178 个布局。去重没有把换色、旋转当成同一种。另有 97 条匹配规则、16 条固定布局。固定布局覆盖进度号 1–11 和 22，同一编号在不同策略组里可以有多条，不能拼成唯一闯关顺序。

难度在子池上是一个区间（最小值和最大值）。固定关索引里看到的 `difficulty=0` 是占位，不是原难度。

带隐藏珠的布局：GP101 有 23,782 条，GP201 有 23,779 条，MF1 有 447 条。带锁的布局：三个池分别是 30,412、30,411、266 条。

## 收集物

核心排序之外还有一层可选收集物，默认关卡演示没有打开。开启时，从「有目标色」的开局绳和补入绳里随机抽 4 到 6 根（`4 + random(0..149) / 50`，再不超过可选绳子数）。这些绳子被收走时各记一次。补入若把该位置换成新的目标绳，收集物身份跟到新目标上；换成临时绳或离场则丢掉。它不改变移动和过关判定。

## 和演示的对应

`RopeSortDemo` 用编号和色块把局面画出来，没有原游戏的绳子动画。操作是点选切口再点目标绳，另有上一条、下一条、按 key 搜索、重开、撤销、取消选择、加一根临时绳。默认打开 `FIXED/1/1`。上一条和下一条按资源索引走，不是玩家闯关顺序。

推进一局的调用顺序：`ColorSortLatticeParser.Parse` → `Validate` → `ColorSortRules.MakeState` → `ApplyMove(state, level, src, cutIndex, dst)` → `IsWin`。
